## 1. commit・push は区切りごとに行う

上書きする共通ルール: 「修正は1点ずつ、確認を重視」「重大な操作の確認方法」の commit・push。

- **作業の区切りごとに commit と push を指示なしで行う**。区切りは、意味のまとまり 1 つ（1 つの修正・1 つの資料・生成物の更新）
- **commit の前に検査を通す**。html2md の指摘 0 件、`check-markdown` と `check-public` も指摘なし。通らなければ commit せずに報告する
- **check-public の誤検出として扱ってよいのは、`docs/js/lib/typescript.js`（TypeScript の配布物）の [認証情報] で、指摘された行がすべて `token` を含むときだけ**。字句解析器の変数名・メソッド名（`token = scanner.scan()` 等）に反応したもの。ほかのファイルに 1 件でも指摘があるか、`token` を含まない行があれば、今までどおり commit せずに報告する
- **check-public は `-a` を付けて流す**。付けないと未追跡のファイルを見ず、新しく足したファイルが検査から漏れる（df0c980 で typescript.js が漏れた）
- **check-public に除外の指定が入ったら、上の扱いをその指定に置き換える**
- **push のあとは、共通ルール「push のあとに公開を確かめる」に従う**
- **変えないもの**: 載せるファイルを名指しで `git add` すること、履歴を書き換える操作（amend・reset・force push）に明示の語が要ること、release・master へのマージに明示の語が要ること
- **理由**: 公開資料を少しずつ進めるプロジェクトで、区切りごとに公開して確かめたいため
