## 1. 目的と現状

### 目的

読者が資料のコードを手元に写さずに試せるようにする。コードの横の「実行」ボタンで、その場で出力（`console.log`）を表示する。**TypeScript の資料なので、型エラーもその場で見せる**。

### 現状（2026-10-09 実測）

| 項目 | 値 |
|---|---|
| 資料内のコードブロック | `typescript` 180 ／ `shell` 39 ／ `json` 10 |
| 実行用サンプル | `docs/samples/` に 13 本（ハンズオン含む）。手元の Node で動かす前提 |
| 資料が対象にする版 | TypeScript 7.0.2 ／ Node v26.10.0 |
| TypeScript 7 の npm パッケージ | `main` が無く `bin/tsc` だけ（`npm view` で確認）。**ブラウザから呼べる JS の API を持たない** |
| ページの JS | `docs/js/highlight.js`（色付け）のみ |

> [!IMPORTANT]
> <strong>ブラウザで動く変換器は、資料の TypeScript 7 と別物になる。</strong>型エラーの文言・検出の細部が資料の記述と食い違う可能性がある（未確認）。食い違いは「進め方」の手順 5・6 のテストで洗い出す。

## 2. 決めたこと

### 参考にした jsprimer の仕組み

| 部分 | jsprimer | この資料 |
|---|---|---|
| 対象の指定 | コードブロックの前に `<!-- js-console -->` を書いたものだけ | 同じ考え方（`data-run`） |
| 実行の場所 | 非表示の iframe ＋ `postMessage`（codemirror-console） | Web Worker |
| 編集 | CodeMirror 5 で編集して再実行 | `textarea` で編集して再実行 |
| 変換 | 無し（JavaScript をそのまま実行） | TypeScript 6.0.3 で型検査と変換 |
| 検証 | power-doctest。`式; // => 値` の注記をビルド時に比較テストへ変換 | 同じ書き方の注記を使う |

### 決定（2026-10-09）

| 論点 | 決定 | 理由 |
|---|---|---|
| 1. 変換器 | TypeScript 6.0.3 の `lib/typescript.js` を `docs/js/lib/` に置く | 型エラーを見せられるのはこれだけ。「実行」を押したときだけ読み込む |
| 2. 実行の場所 | Web Worker | 無限ループでもページが固まらず、時間切れで止められる |
| 3. 対象の指定 | `<pre data-run>` を付けたものだけ | 断片・Node 専用の例に動かないボタンを並べない |
| 4. 編集 | `textarea` に差し替えて編集・再実行できる | ライブラリを増やさずに「書き換えて試す」を再現する |
| 5. 検証 | コードに `// => 値` の注記を書き、テストで照合する | 結果を貼っていないコードも検証でき、読者には行の横に答えが見える |

> [!IMPORTANT]
> <strong>注記は `data-run` を付けるコードにだけ書く。</strong>型エラーは注記ではなく、エラー番号（`TS2345` 等）で照合する。既存の `$ npx tsx` の結果ブロックと内容が重なるものは、手順 4 で残すか消すかを決める。

## 3. 作るもの

| 置き場 | 中身 |
|---|---|
| `docs/js/lib/` | 変換器の本体（1 の結果）と、そのライセンス文。版はファイルの先頭のコメントと `docs/ZZ-構成.html` に記す |
| `docs/js/runner.js` | `pre[data-run]` にボタンと出力欄を足す。押されたら変換器を読み込み、型エラーと出力を表示する |
| `docs/js/runner-worker.js` | Worker 側。変換したコードを実行し、出力を親へ返す |
| `docs/css/style.css` | ボタン・出力欄・型エラーの見た目 |
| `docs/*.html` | 対象の `pre` に `data-run` を付ける。`runner.js` を読み込む |
| `tests/` | 資料の `data-run` コードを取り出し、`// => 値` の注記を比較に変えて `node:test` で実行する。型エラーは番号で照合する |

- **ボタンと出力欄は JS が足す**。HTML には置かないので、Markdown には出ない（`md-skip` は要らない）
- **JS が動かないときは今のまま**（コードと貼った実行結果が読める）

### 手順

### 結果（2026-10-12）

#### data-run を付けたもの（手順 4）

`console.log` を含むコード例 53 本を、`tools/40_test/list-runnable.ts` で型検査・実行して選んだ。**17 本**に付けた（01・02・04・05・06・07・08・09・11・A2）。

| 外したもの | 理由 |
|---|---|
| 実行の途中で例外が出るもの（03 #1、06 #6・#7 など） | 注記は出力の並びなので、例外で止まる様子を表せない |
| `import`・`await`・`process`・`fs` を使うもの（10〜12・A3 など） | ブラウザの Worker では動かない。`docs/samples/` で手元の Node に任せる |
| 未定義の名前を使う断片（A2 #2・#5 など） | 前後のコードが無いと動かない |
| 出力の無いもの | 「実行」しても見せるものが無い |

**貼ってある `$ npx tsx` の結果ブロックは残した**。JS が動かない読者と Markdown の読者のため。注記と同じ内容であることをテストで確かめる。

#### 注記とテスト（手順 5・6）

- 注記は出力を起こす行の末尾に `// => 出力`。ループのように 1 行で何度も出力するものは、ループの後ろに `// =>` の行を重ねる。型エラーはコメントの `error TSxxxx`（`エラー TSxxxx`）で照合する
- `tests/samples-run.test.ts`: 型エラーの番号、Worker の整形、本物の Node の出力、貼った実行結果の 4 つを注記と比べる
- `tests/browser/runner.spec.ts`: chromium・firefox・webkit で「実行」を押し、出力を注記と比べる。編集・型エラー表示・時間切れ・JS が足す部品の配色も確かめる
- 照合を作る途中で、01・02 章と ZZ の打ち間違いの例の型エラーが、資料の `TS2353` ではなく `TS2561` だと分かった（7.0.2・6.0.3 とも）。直した
